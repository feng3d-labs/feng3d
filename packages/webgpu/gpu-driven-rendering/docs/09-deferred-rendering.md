## 概述

延迟渲染（Deferred Rendering）将几何处理和光照计算分离到两个渲染Pass，通过中间的G-Buffer（几何缓冲）存储几何信息，在光照Pass中统一计算光照。

### 设计目标

- **多光源优化**：支持100+动态光源场景
- **GPU驱动**：剔除、命令生成全GPU驱动
- **透明混合**：支持透明物体的前向渲染混合
- **高效内存**：优化G-Buffer布局和带宽

## 渲染流程

### 完整流程

```
┌─────────────────────────────────────────────────────────────┐
│                    延迟渲染流程                               │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│  【GPU计算阶段】                                              │
│  1. GPU Culling                  （视锥/遮挡剔除）             │
│  2. LOD Selection                （LOD选择）                  │
│  3. Command Generation           （生成绘制命令）              │
│                                                              │
│  【G-Buffer Pass】                                           │
│  4. 渲染不透明物体到G-Buffer         （4-8个RT）              │
│     ├── World Position                                        │
│     ├── World Normal                                          │
│     ├── Albedo + Alpha                                        │
│     ├── Material Props (roughness, metallic, emissive)       │
│     └── Motion Vectors (可选)                                 │
│                                                              │
│  【Lighting Pass】                                            │
│  5. 光照计算                      （全屏四边形/瓦片）          │
│     ├── 读取G-Buffer                                           │
│     ├── 遍历光源                                              │
│     ├── PBR着色计算                                           │
│     └── 输出光照结果                                          │
│                                                              │
│  【透明前向Pass】                                             │
│  6. 透明物体前向渲染                （深度排序后绘制）          │
│     ├── 读取深度缓冲                                           │
│     ├── 前向光照计算                                           │
│     └── Alpha混合                                             │
│                                                              │
│  【后处理Pass】                                               │
│  7. Tone Mapping                                               │
│  8. Bloom / Glow                                              │
│  9. Anti-Aliasing                                             │
│                                                              │
└─────────────────────────────────────────────────────────────┘
```

## G-Buffer设计

### 布局方案

| 方案 | RT数量 | 带宽 | 质量 | 兼容性 |
|------|--------|------|------|--------|
| **标准4RT** | 4 | 中 | 高 | 广泛 |
| **紧凑3RT** | 3 | 低 | 中 | 广泛 |
| **扩展8RT** | 8 | 高 | 极高 | 有限 |

### 标准4RT布局

| RT | 格式 | 通道 | 内容 |
|----|------|------|------|
| **GBuffer0** | RGBA16F | RGB | World Position |
| | | A | Linear Depth |
| **GBuffer1** | RGB10A2 | RGB | World Normal (encoded) |
| | | A | - |
| **GBuffer2** | RGBA8 | RGB | Albedo |
| | | A | Opacity |
| **GBuffer3** | RGBA8 | R | Roughness |
| | | G | Metallic |
| | | B | Emissive |
| | | A | Material ID |

### 数据优化

- **Normal Encoding**：使用球面坐标或八面体编码减少精度损失
- **Depth Packing**：线性深度存储在Position的Alpha通道
- **通道合并**：将粗糙度、金属度、自发光合并到一个RT

## 光照Pass设计

### 全屏四边形方式

最简单的实现方式，一个全屏Pass处理所有像素。

```
优点：
- 实现简单
- 易于调试
- 无需预计算

缺点：
- 所有像素遍历所有光源（浪费）
- 不适合大量光源
```

### Tiled Lighting（瓦片光照）

将屏幕划分为16x16或32x32的瓦片，每个瓦片构建光源列表。

```
┌─────────────────────────────────────────────────────────────┐
│                    瓦片光照流程                               │
├─────────────────────────────────────────────────────────────┤
│  1. 深度Bounds计算              （每个瓦片的最小/最大深度）    │
│  2. 光源剔除                    （剔除不影响该瓦片的光源）      │
│  3. 构建光源列表                （存储影响该瓦片的光源索引）    │
│  4. 瓦片光照计算                （遍历光源列表计算光照）        │
└─────────────────────────────────────────────────────────────┘
```

### Clustered Lighting（聚类光照）

在Tiled基础上增加深度维度，将场景分为3D聚类。

```
优势：
- 更精确的光源剔除
- 支持点光源的精确体积剔除
- 适合复杂场景

开销：
- 更多计算
- 更多内存
```

## 透明物体处理

### 问题

延迟渲染难以处理透明物体，因为：
- 透明物体需要按深度排序
- 透明度混合需要访问背景颜色
- G-Buffer不适用于透明物体

### 解决方案：前向混合Pass

```
┌─────────────────────────────────────────────────────────────┐
│                透明物体前向混合Pass                           │
├─────────────────────────────────────────────────────────────┤
│  1. 从深度缓冲读取深度                                         │
│  2. GPU驱动透明物体排序            （Bitonic Sort）            │
│  3. 前向渲染透明物体                                          │
│  4. Alpha混合到光照缓冲                                       │
└─────────────────────────────────────────────────────────────┘
```

### 混合策略

| 策略 | 说明 | 性能 | 质量 |
|------|------|------|------|
| **全前向** | 透明物体完全前向渲染 | 中 | 高 |
| **深度排序** | Bitonic Sort + 批量渲染 | 高 | 高 |
| **OIT** | Order Independent Transparency | 低 | 极高 |

## GPU驱动集成

### 命令生成

延迟渲染的G-Buffer Pass由GPU生成绘制命令，与主渲染共享剔除结果。

```
计算着色器任务：
1. 读取剔除结果        （复用主渲染剔除数据）
2. 分类不透明/透明物体  （分离渲染路径）
3. 生成G-Buffer命令    （不透明物体绘制）
4. 生成透明命令        （透明物体排序）
```

### 资源管理

- **G-Buffer Pool**：支持多帧并行的G-Buffer池
- **Light Buffer**：存储所有光源信息的SSBO
- **Tile Light List**：瓦片光源列表缓冲

## 性能优化

### 带宽优化

| 技术 | 说明 | 效果 |
|------|------|------|
| **Early-Z** | 提前深度测试 | 减少overdraw |
| **Depth PrePass** | 预先渲染深度 | 优化overdraw |
| **Tile Culling** | 瓦片级别光源剔除 | 减少光源计算 |
| **Light Culling** | 光源体积剔除 | 精确剔除 |

### 内存优化

- **格式选择**：使用最小够用的纹理格式
- **通道合并**：合并不需要独立精度的数据
- **压缩纹理**：Albedo使用BC7等压缩格式

### 渲染优化

- **Async Compute**：光照计算使用异步计算队列
- **Variable Rate Shading**：远处区域降低着色频率
- **Multi-View**：立体渲染共享G-Buffer

## 与前向渲染对比

| 特性 | 延迟渲染 | 前向渲染 |
|------|----------|----------|
| 光源数量 | 100+ | < 10 |
| 透明物体 | 需额外Pass | 原生支持 |
| 内存占用 | 高 | 低 |
| 带宽消耗 | 高 | 中 |
| 实现复杂度 | 高 | 低 |
| 后处理 | 灵活 | 受限 |

## 应用场景

### 适合延迟渲染

- 开放世界场景
- 大量动态光源（夜间、室内）
- 复杂光照效果
- PC/主机平台

### 适合前向渲染

- 移动平台
- 少量光源场景
- 大量透明物体
- VR应用

# 架构概览

## 核心目标

WebGPU 全GPU驱动渲染系统致力于实现以下核心目标：

- **全GPU驱动**：视锥剔除、遮挡剔除、LOD选择、深度排序、材质分组、渲染命令生成，均由GPU完成，CPU仅负责下发初始化及渲染指令

- **高性能**：不透明物体批量绘制，透明物体保证渲染正确性的同时最小化CPU开销

- **可扩展性**：支持多材质、多渲染路径，适配不同类型物体（PBR、无光照、透明、特效等）

- **多路径支持**：架构支持前向渲染、延迟渲染、Forward+、光线追踪等多种渲染路径

- **无冗余开销**：避免CPU-GPU数据回读（仅透明物体需读取极小量批次信息），不做无意义的管线/缓冲切换

## 当前架构

### 渲染路径：前向渲染

**状态**：✅ 当前实现
**特点**：
- 直接绘制物体，光照在像素着色器中计算
- 适合少量光源、简单场景
- 易于实现，兼容性好

### 系统流程图

```text
【CPU端】
  初始化：上传全局资源（顶点/索引/材质/纹理）→ 创建管线/BindGroup
  每帧：上传相机参数 → 录制渲染命令 → 提交GPU执行

【GPU端】
  计算着色器1：视锥剔除 + 遮挡剔除 + LOD选择 + 物体分类（不透明/透明）
  计算着色器2：透明物体 → 深度聚类+材质聚合排序（Bitonic Sort）
  计算着色器3：Hi-Z金字塔生成（可选，用于遮挡剔除）
  渲染管线：不透明批量绘制 → 透明批量绘制（按批次） → 后处理
```

## 混合渲染架构

现代3A引擎并非选择单一渲染路径，而是在同一帧内混合使用多种渲染技术，根据对象特性选择最合适的渲染方式。

### 设计理念

```
核心思想：不同对象用不同技术，统一协调输出

对象类型              最适合技术              原因
─────────────────────────────────────────────────
静态不透明几何        延迟渲染                多光源优化
动态角色/物体        前向渲染                复杂着色、透明
玻璃/水面            光线追踪                真实反射
远景天空/背景        SDF光线前进             无限细节
透明粒子             前向渲染                Alpha混合
体积雾/云            SDF/体积渲染            体积效果
UI/HUD               2D渲染                  覆盖层
```

### 单帧混合渲染流程

```
┌─────────────────────────────────────────────────────────────┐
│                典型混合渲染单帧流程                          │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│  Pass 1: Shadow Depth Pass      (光栅化)                      │
│  ├─ 定向光源深度                                             │
│  ├─ 聚光灯深度                                               │
│  └─ 点光源深度                                               │
│           ↓ 写入 Shadow Maps                                 │
│                                                              │
│  Pass 2: Depth PrePass          (光栅化 - 前向/延迟)           │
│  ├─ 不透明几何体                                             │
│  └─ 写入深度缓冲                                             │
│           ↓ 所有后续Pass读取深度                              │
│                                                              │
│  Pass 3: G-Buffer Pass          (延迟渲染)                    │
│  ├─ 建筑、车辆等静态几何                                     │
│  └─ 输出: Position, Normal, Albedo, Material                │
│                                                              │
│  Pass 4: 延迟光照 Pass          (延迟渲染)                    │
│  ├─ 全屏四边形/瓦片光照                                      │
│  ├─ 读取G-Buffer                                            │
│  └─ 输出光照结果                                             │
│                                                              │
│  Pass 5: Ray Traced Effects    (光线追踪)                    │
│  ├─ 反射 (玻璃、金属)                                        │
│  ├─ 软阴影                                                   │
│  └─ 输出到光照缓冲                                           │
│                                                              │
│  Pass 6: SDF Background        (SDF光线前进)                  │
│  ├─ 远景、天空、程序化背景                                    │
│  ├─ 读取深度，只渲染未击中像素                                │
│  └─ 输出颜色到光照缓冲                                       │
│                                                              │
│  Pass 7: 前向不透明 Pass        (前向渲染)                    │
│  ├─ 角色、动态物体                                           │
│  ├─ 深度测试等于（Z-Equal）                                  │
│  └─ 输出到光照缓冲                                           │
│                                                              │
│  Pass 8: 3D Gaussian Splatting (3DGS)                        │
│  ├─ 高斯椭球体渲染                                           │
│  ├─ GPU深度排序（从前到后）                                  │
│  ├─ Alpha混合累积                                            │
│  └─ 输出到光照缓冲                                           │
│                                                              │
│  Pass 9: 透明渲染 Pass         (前向渲染)                    │
│  ├─ 粒子系统、透明物体                                       │
│  ├─ GPU深度排序                                              │
│  └─ Alpha混合到光照缓冲                                      │
│                                                              │
│  Pass 10: 后处理 Pass                                                   │
│  ├─ Tone Mapping                                             │
│  ├─ Bloom / TAA                                             │
│  └─ 输出最终图像                                             │
│                                                              │
└─────────────────────────────────────────────────────────────┘
```

### 协调机制

#### 深度缓冲协调

```
共享深度缓冲策略：

┌─────────────────────────────────────────────────────────────┐
│  写入者          │  读取者                    │  用途         │
├─────────────────────────────────────────────────────────────┤
│  Shadow Pass    │  -                        │  阴影生成      │
│  Z-PrePass      │  延迟、光线追踪、SDF       │  深度测试      │
│  延迟渲染       │  -                        │  G-Buffer深度  │
│  前向渲染       │  后续Pass                  │  不透明深度    │
│  透明渲染       │  - (通常不写入)            │  排序参考      │
└─────────────────────────────────────────────────────────────┘

深度用途：
• 延迟渲染：从G-Buffer重建深度
• 光线追踪：Ray Origin偏移，depth testing
• SDF：击中检测，背景填充
• 前向渲染：深度测试，early-z
```

### 渲染顺序原则

```
正确顺序的关键规则：

1. 先生成阴影 (Shadow Pass)
   └─ 所有需要阴影的Pass依赖此

2. 建立深度 (Z-PrePass)
   └─ 后续Pass可做depth testing

3. 不透明延迟渲染 (G-Buffer + 光照)
   └─ 利用深度测试，主要几何体

4. 光线追踪效果
   └─ 读取深度，叠加到光照缓冲

5. SDF/程序化背景
   └─ 填充未击中像素的背景

6. 前向不透明
   └─ 深度等于(Z-Equal)，复杂着色

7. 3D Gaussian Splatting
   └─ 深度排序后，从前到后Alpha累积

8. 透明物体
   └─ 深度排序后，Alpha混合

9. 后处理
   └─ 全屏效果，色调映射
```

### 性能考虑

```
混合渲染的性能优化：

1. 合理排序
   └─ 深度前置减少overdraw
   └─ 费用高的Pass尽量早执行(可利用depth culling)

2. 视锥剔除
   └─ 所有路径共享剔除结果
   └─ 减少无效绘制

3. 分辨率缩放
   └─ 光线追踪/SDF可降低分辨率
   └─ 后处理上采样

4. 异步计算
   └─ 光线追踪使用独立队列
   └─ 与主渲染并行

5. LOD
   └─ 远处物体降低精度
   └─ SDF可自适应采样
```

## 核心设计原则

### 1. 巨型缓冲原则

所有顶点、索引、材质、纹理均一次性上传至全局巨型缓冲，不动态切换缓冲，仅通过"偏移/索引"实现资源切换。

**优势**：
- 减少资源绑定开销
- 避免频繁的buffer切换
- 简化资源管理

### 2. GPU自治原则

除管线切换、相机参数上传外，所有渲染相关逻辑（剔除、排序、命令生成）均由GPU计算着色器完成。

**优势**：
- CPU负载降至最低
- GPU并行计算效率最大化
- 消除CPU-GPU同步瓶颈

### 3. 分层渲染原则

不透明物体优先渲染（深度测试自动解决覆盖），透明物体后渲染（严格按深度排序保证混合正确）。

**渲染顺序**：
1. 不透明物体（按材质分组批量绘制）
2. 透明物体（按深度聚类+材质聚合排序后批量绘制）
3. 后处理效果

### 4. 最小回读原则

仅透明物体需回读极小量批次信息（数十到数百字节），其余数据均在GPU内部流转。

**回读内容**：
- 透明物体的批次分组信息
- 批次数量（按材质类型）

### 5. 深度聚类原则

透明物体按"深度聚类+材质聚合"排序，保证视觉效果正确的同时减少管线切换。

**核心思想**：
- 相近深度的物体（聚类内）顺序可互换，不影响视觉效果
- 同一聚类内按材质聚合，减少管线切换
- 不同聚类间严格按深度排序

### 6. 多路径可扩展原则

架构设计为支持多种渲染路径，核心组件共享，渲染路径可插拔。

**设计要点**：
- 抽象渲染路径接口
- 运行时路径切换
- 共享基础组件

## 系统组件

### CPU端组件

| 组件 | 职责 |
|------|------|
| 资源管理器 | 上传全局资源、创建缓冲和纹理 |
| 管线管理器 | 创建和管理渲染管线 |
| 渲染路径管理器 | 管理和切换渲染路径 |
| 命令录制器 | 录制渲染命令（极简操作） |
| 相机控制器 | 每帧上传相机参数 |

### GPU端组件

| 组件 | 职责 |
|------|------|
| 视锥剔除着色器 | 检测物体是否在视锥内 |
| 遮挡剔除着色器 | Hi-Z深度检测剔除被遮挡物体 |

| 排序着色器 | 透明物体深度聚类+材质聚合排序 |
| 渲染管线 | 执行批量绘制 |

## 概述

Forward+（也称为 Tiled Forward Rendering 或 Clustered Forward Rendering）是一种结合前向渲染简单性和延迟渲染多光源优势的渲染技术。通过将屏幕空间划分为瓦片（Tiled）或体积聚类（Clustered），每个区域仅计算影响它的光源，从而高效支持大量动态光源。

### 核心思想

传统前向渲染的问题是每个片段都要遍历所有光源。Forward+ 通过预计算每个区域的光源列表，使片段着色器仅遍历相关光源。

### 设计目标

- **多光源支持**：高效处理10-100+动态光源
- **透明原生支持**：保持前向渲染的透明渲染优势
- **MSAA兼容**：支持多重采样抗锯齿
- **GPU驱动**：光照列表生成由GPU完成

## 光照分块算法

### Tiled Forward（瓦片前向渲染）

将屏幕划分为规则的2D瓦片网格。

#### 瓦片划分

```
屏幕划分示例 (1920x1080, 32x32瓦片):
┌─────────────────────────────────────────────────────────────┐
│ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │
│─┼─┼─┼─┼─┼─┼─┼─┼─┼─┼─┼─┼─┼─┼─┼─┼─┼─┼─┼─┼─┼─┼─┼─┼─┼─┼─┤
│ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │
│─┼─┼─┼─┼─┼─┼─┼─┼─┼─┼─┼─┼─┼─┼─┼─┼─┼─┼─┼─┼─┼─┼─┼─┼─┼─┼─┤
│ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │
│─┼─┼─┼─┼─┼─┼─┼─┼─┼─┼─┼─┼─┼─┼─┼─┼─┼─┼─┼─┼─┼─┼─┼─┼─┼─┼─┤
│ │[瓦片60]│[瓦片61]│...  │ │  每个瓦片存储影响它的光源列表      │
│─┼───────┼───────┼─────┼─┤                                  │
│ │       │       │     │ │                                  │
│ └───────┴───────┴─────┘─┘                                  │
│                                                              │
│  瓦片大小：32x32 像素（可配置 16/32/64）                       │
│  总瓦片数：60 x 34 = 2040                                    │
│  每瓦片最大光源数：128（可配置）                              │
└─────────────────────────────────────────────────────────────┘
```

#### 光照列表结构

每个瓦片存储：
- 光源计数（uint）
- 光源索引数组（uint[128]）

#### 计算着色器流程

1. 每个工作组处理一个瓦片
2. 遍历深度缓冲，找到最小/最大深度
3. 根据深度范围构建光源包围盒
4. 测试每个光源是否与瓦片包围盒相交
5. 将相交光源索引写入列表

### Clustered Forward（聚类前向渲染）

在瓦片基础上增加深度维度，将场景划分为3D聚类。

#### 聚类划分

```
3D聚类划分示例:
┌─────────────────────────────────────────────────────────────┐
│                         相机                                 │
│                          ◆                                   │
│                         ╱│╲                                  │
│                        ╱ │ ╲                                 │
│              ┌─────────┼─────────────┐                       │
│              │ Near   │   Mid       │  Far                  │
│              │ Cluster│  Clusters  │ Clusters               │
│              │        │            │                        │
│              │ ■ ■ ■  │  ■ ■ ■     │  ■ ■ ■                 │
│              │ ■ ■ ■  │  ■ ■ ■     │  ■ ■ ■                 │
│              │ ■ ■ ■  │  ■ ■ ■     │  ■ ■ ■                 │
│              └─────────┼─────────────┘                       │
│                                                              │
│  深度分层：对数分布（近密远疏）                                │
│  每层瓦片：32x32                                              │
│  总聚类数：瓦片数 × 分层数                                    │
└─────────────────────────────────────────────────────────────┘
```

#### 深度分层策略

| 策略 | 说明 | 优势 |
|------|------|------|
| **线性** | 等间距分层 | 简单 |
| **对数** | 近密远疏 | 符合视觉 |
| **指数** | 指数分布 | 精度平衡 |
| **自适应** | 根据场景内容 | 最优 |

#### 优势

- 精确的点光源体积剔除
- 更好的光源分布
- 减少无效光照计算
- 适合3D场景

## 深度PrePass

### 目的

预先渲染深度信息，用于：
- 构建更精确的深度Bounds
- 优化overdraw
- 提供深度信息给光照计算

### 可选性

深度PrePass是可选的：
- **启用**：复杂场景、overdraw严重时
- **禁用**：简单场景、性能优先时

## 光照列表生成

### 数据结构

#### 瓦片数据

```c
// 瓦片/聚类光照列表
struct TileLightList {
    uint lightCount;           // 光源数量
    uint lightIndices[128];    // 光源索引
};

// 深度Bounds
struct DepthBounds {
    float minDepth;            // 最小深度
    float maxDepth;            // 最大深度
};
```

#### 全局缓冲区

```c
// 所有瓦片的光照列表
struct TileLightData {
    DepthBounds depthBounds[numTiles];
    TileLightList lightLists[numTiles];
};
```

### 计算流程

#### 1. 深度Bounds计算

每个瓦片/聚类独立计算：
- 读取瓦片内所有像素深度
- 找到最小/最大深度
- 存储到depthBounds

#### 2. 光源剔除

对每个光源：
- 构建光源包围盒（球体/圆锥体）
- 测试包围盒是否与瓦片/聚类相交
- 相交则加入列表

#### 3. 列表构建

- 将通过剔除测试的光源索引写入列表
- 更新光源计数
- 处理光源超限（截断或排序）

## 主渲染Pass

### 不透明物体渲染

片段着色器读取光照列表：

```
渲染流程：
1. 计算像素所属瓦片/聚类索引
2. 读取该区域的光照列表
3. 仅遍历列表中的光源
4. 累加光照结果
```

### 透明物体渲染

- 保持前向渲染的深度排序
- 读取光照列表计算光照
- Alpha混合到帧缓冲

## GPU驱动集成

### 计算着色器职责

```
GPU计算阶段：
1. 读取剔除结果              （复用主渲染数据）
2. 分离不透明/透明物体
3. 生成深度PrePass命令        （可选）
4. 生成主渲染Pass命令
5. 触发光照列表生成
```

### 命令缓冲区

- **DepthPrePassBuffer**：深度PrePass绘制命令
- **MainPassBuffer**：主渲染Pass绘制命令
- **TransparentPassBuffer**：透明渲染绘制命令

## 性能优化

### 瓦片大小选择

| 大小 | 瓦片数 | 光源剔除精度 | 内存占用 | 推荐场景 |
|------|--------|--------------|----------|----------|
| 16x16 | 多 | 高 | 大 | 光源密集 |
| 32x32 | 中 | 中 | 中 | 平衡 |
| 64x64 | 少 | 低 | 小 | 光源稀疏 |

### 深度分层策略

- **对数分层**：近密远疏，符合视觉感知
- **动态分层**：根据场景深度分布调整
- **固定分层**：简单但不够灵活

### 内存优化

- **紧凑存储**：使用uint16存储光源索引（<65536光源）
- **列表压缩**：使用变长列表
- **Double Buffering**：避免同步等待

## 应用场景

### 最适合

- 中等规模动态光源（10-100）
- 混合透明/不透明场景
- 需要MSAA的场景
- 开放世界日/夜循环
- 室内/室外混合场景

### 不适合

- 少量光源（前向渲染更简单）
- 极多光源（延迟渲染更高效）
- 纯透明场景（前向渲染更直接）

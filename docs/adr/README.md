# 架构决策记录（ADR）

> 状态：**现行**。本目录收录「已经拍板、且以后会有人问为什么」的决策。

## 什么该进这里

三条**全部**满足才收：

1. **Hard to reverse** —— 反悔代价高（改协议、改分层、改数据格式、改目录约定）；
2. **Surprising without context** —— 不知道背景的人会觉得奇怪（"为什么不用 X / 为什么不合并"）；
3. **The result of a real trade-off** —— 是权衡的结果，不是唯一解。

**任何一条不满足就不收。** 日常实现选择、一眼能看懂的约定，写进代码注释或根 `AGENTS.md` 就够了——
收多了会让本目录变成 sediment，反而没人翻。

## 文件格式

`NNNN-短横线标题.md`，从 `0001` 起编号，**只增不改**（要改就新写一条，标注取代关系）。

```markdown
# NNNN. <决策标题>

> 状态：已采纳（YYYY-MM） / 已被 NNNN 取代

## 背景
什么情况下必须做这个决策

## 决策
决定了什么

## 为什么
权衡了什么、放弃了哪些方案、各自的代价

## 影响
哪些代码/文档受它约束；违反它会被哪个门禁拦住（没有门禁的，按根 AGENTS.md §15 只算建议）
```

## 为什么"只增不改"

决策**不随代码变**，所以它是唯一"越写越值钱"的文档类型。而"改"会让读者失去"当时为什么这么定"的记录——
那正是后来者最需要的东西。
